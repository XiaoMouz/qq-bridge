# Mac 输入与快速回复草稿实机复验（2026-10-15）

## 自动化焦点问题

前几轮仅按辅助功能索引点击输入框后，粘贴没有写入，setValue 提示目标不可设置。此次检查正常应用截图时窗口处于非激活样式；按实际截图坐标点击输入框后，英文 typeText 正常写入，辅助功能树将输入框标为 settable 并返回完整 Value。随后中文 paste 正常写入。因此这些失败不能作为 ComposerTextView 的产品缺陷证据，也不需据此修改焦点实现。

工具的中文 typeText 未写入字符，英文 typeText 和中文 paste 均可用。验收只覆盖英文键入和中文粘贴，不代表中文输入法候选／组字回车已经测试。

## 最终正常应用的实际操作

没有临时菜单、测试宿主或替代数据，全部在 Something 的当前正常聊天页：

1. 实际点击输入框，键入英文草稿并粘贴中文，辅助功能值确认成功。
2. Shift-Return 和 Option-Return 分别插入换行，草稿仍留在输入框；英文标记确认三行内容，没有发送。
3. ⌘3 切到设置，⌘1 回消息，三行草稿完整保留。
4. 会话右键→快速回复，三行草稿完整交接；实际点击快速回复输入框并粘贴中文后缀。
5. 鼠标关闭快速回复后，主会话收到修改后的完整草稿；重开后同一草稿仍在，Esc 返回也完整保留。
6. 实际点击主输入框，用 ⌘A / Backspace 清空本轮草稿；最终输入框为空，恢复录音入口。

本轮没有代码变更，不重复构建或全量测试；不发送消息、不改变系统键盘导航设置。完整 Tab / Shift-Tab 控件巡航、VoiceOver 和中文输入法候选仍未验收。此次为正常会话右键入口，不能代替带文字草稿的真实新消息横幅触发验收。
