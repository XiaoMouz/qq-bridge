## 相册分页恢复与 MVVM（2026-10-15）

旧照片页失败后直接设 `hasMore = false`，首屏无重试入口，后续失败会把照片列表永久截断。Mac 现由独立服务封装原 RPC，ViewModel 持有请求、游标、数据与错误，视图只渲染状态和操作；iOS 分支沿用原实现。

- 请求失败保留当前照片和原游标，显式重试同一页；已有照片时错误提示放在列表末尾。
- 首屏超时显示“照片加载失败 / 加载超时，请重试”，可以直接重试。
- 空页但服务端仍报告下一页时显示“当前页没有照片”和“加载更多”，避免误报空相册。
- 同页与跨页重复 ID 只显示一次；同时触发不会重复请求，重复游标停止自动翻页并允许手动重试。
- 离开页面取消请求，旧响应即使迟到也不能覆盖新的数据。照片按日期分组，画廊索引仍基于去重后的完整列表。

使用临时 DEBUG 入口注入受控服务，复用生产 MacAlbumMediaView、ViewModel、RemoteImage 与 URLGallery。服务按顺序模拟首屏超时→空的中间页→三张照片→下一页超时→含一个重复项的末页；图片为此前本机生成的蓝/黄 PNG，仅通过 127.0.0.1:18463 提供，没有上传或操作真实群数据。

440×480 实测上述完整流程：错误和重试按钮可见；下一页失败时三张照片保留；重试后六张照片、没有重复项、错误提示消失；点击第六张进入 6/6，Esc 返回仍保留六张。切到 1024×640 后三列保持，滚动能完整看到最后一行。截图在 `/tmp/betterchat-ui-review/`：`album-first-error-440.png`、`album-empty-page-440.png`、`album-next-error-440.png`、`album-retry-success-440.png`、`album-retry-success-wide.png`。

临时菜单与源码已移除，本机素材服务已停止。六项真实模型测试验证异常路径，受控 UI 检查不替代真实长相册完整分页终点；未改手机相册或图片编辑功能。Claude 仍在已确认的额度限制期间，本轮没有标为双方联合终验。
