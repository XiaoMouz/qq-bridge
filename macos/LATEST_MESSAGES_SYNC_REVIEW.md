# 切换会话偶发停在旧消息：修复与验证（2026-10-15）

## 已复现的问题

1. 本地尚未缓存的会话，`catchUpChat` 将“本地 chat_pts 为 0”当成同步结束条件。服务端单会话差量并非总是直接返回最新一屏：例如 75 条变化、每页 50 条时，第一响应仍是 `isFinal = false`。原客户端收到前 50 条后就返回，直到下一次同步才继续。
2. `SyncEngine` 是 actor，但网络请求等待期间可以重入。后台预取与打开会话交错时，迟到的 `tooLong` 响应会清空另一个请求刚更新的消息窗口，并回退会话游标。反向交错也会发生。
3. 页面原先用 `try?` 忽略打开会话时的同步错误，用户只能看到旧列表。

## 修改

- 单会话追平以 `isFinal` 为结束条件；批量预取返回非最终页时继续追平。
- 响应写库前核对请求起点与当前会话游标。已有其他请求推进时，不再应用旧快照；必要时从新游标补齐。
- 聊天页将最新消息同步与成员资料加载拆开。失败提供“最新消息同步失败 / 重试”，重新选择当前会话或连接恢复后重新补拉；任务随页面消失取消，取消后的错误不覆盖当前页面。
- 修改位于共享同步引擎与共享聊天页，Mac 和 iOS 都使用修复后的逻辑；未改协议或服务端。

## 验证

- 修复后：新增五项回归，包括批量预取续页，以及并发打开只追到批量响应之前时从新游标补齐。Swift 包完整 43 项测试通过，含原有取消后迟到响应检查。日志 `/tmp/betterchat-chat-races-final-tests.log`。
