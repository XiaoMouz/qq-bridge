# 会话列表操作恢复复验

2026-10-15。Opus 5.5（auto）复核并实现错误状态与 UI，Codex 核对源码、运行测试并执行实机检查。修复前结论见 [Opus 评审](OPUS_DIALOGS_REVIEW.md)，未读导航与菜单另见 [未读复验](UNREAD_NAVIGATION_REVIEW.md)。本轮仅修改 Mac 实现。

## 改动

- 失败按独立身份排队，写操作提示含会话名和动作。关闭一条不清掉后来的失败，不自动重放写操作。
- 本地库观察失败保留已有会话和角标，提供明确重试；“稍后”后可由设置 → 同步再次启动观察，保留原更新回调。
- 同一会话的写入按用户提交顺序执行，不同会话互不等待。前一条失败不重发，后续已提交动作继续；模型释放后等待中的操作不会再提交。
- UIKit 一次呈现一条错误。隐藏的窄窗口列表待返回后再提示，关闭动画结束后继续下一条。
- 无未读目标时快捷键保留页面与搜索；有目标直接打开，避免先退列表。已读会话隐藏“标为已读”，与 iOS 条件一致。

## 自动检查

新增四项 `MacDialogsTests` 运行真实生产 ViewModel，使用可控 continuation：错误排队和按身份确认、观察保留/显式重试与角标回调、逐会话顺序与跨会话并发、释放时取消等待写入。四项通过，日志 `/tmp/betterchat-dialog-recovery-tests.log`。

当前应用共有 192 项测试声明。本轮四项为专项执行，不是全量 192 项。此前全量 186 项及新增两项登录布局的结果仍分别有效，不混称一次运行。

## 实机受控检查

临时服务只代理真实本地库观察，所有会话写方法均直接返回本地失败，不向服务器提交。菜单触发生产 ViewModel 的两次动作，沿实际列表控制器呈现错误；观察流可受控结束，再由生产重试路径重新连接。不是断网或数据库真实损坏测试。

1. 1024×640：取消置顶失败 → 鼠标“好” → 免打扰失败 → “好” → 恢复 Something。两条未互相覆盖。
2. 观察流失败：已有列表保留，出现“会话列表停止更新”；鼠标“重试”后新观察建立，可再次触发同一失败，证明重试实际发生。
3. 观察失败选择“稍后” → 设置 → 同步 → 立即同步，显示同步完成；返回消息后可再次结束新观察并出现提示，证明设置入口恢复了观察。
4. 440×480：Something 详情中触发两次失败，没有打断聊天；通过 Back 返回列表后显示第一条，确认后显示第二条，最终恢复列表。
5. 深色操作失败及浅色观察失败提示文字、按钮可读，鼠标重试完成。恢复跟随系统外观与 1024×640。
