# 视频画中画运行复验（2026-10-15）

## 实际范围

通过临时 Debug 菜单将本地 60 秒 H.264 静音素材交给生产 `MacMediaWindows`、`URLGalleryView` 和 `MacVideoControlsButton`，不上传、不发消息。原有播放器代码没有最终改动；临时菜单、素材和回调探针均移除。

原实现实际通过：

- 独立媒体窗口 → 打开系统播放器 → “最小化视频”，系统 `PIPAgent` 显示 Picture in Picture 浮动窗口。
- 小窗有关闭、恢复、后退 10 秒、播放/暂停、前进 10 秒系统控件。
- 播放时素材帧计数推进；暂停后按钮变为 Play。向前和向后跳转改变素材时间码，恢复原窗口保留约 6.7 秒的暂停位置。
- 再次进入小窗后可以播放并关闭小窗，原媒体窗口仍可打开播放器。
- 最后关闭来源媒体窗口，主聊天仍保持 Something。此后读取 PIPAgent 两次超时，不能把工具超时当作完整资源释放证据。

截图在 `/tmp/betterchat-ui-review/`：`pip-baseline-paused.png`、`pip-baseline-forward.png`、`pip-baseline-restored.png`。截图中的内容只有本地测试色条，没有真实聊天媒体。

## 诊断结论与边界

最初只截 BetterChat 窗口，没有看到系统浮动小窗，错误怀疑播放器被提前释放。临时代理实际收到 willStart / didStart，随后连接 `PIPAgent` 看到了小窗。撤回试验性的强引用修改和代理，再从原生产实现重新测试，上述交互仍通过。因此不保留未经证实必要的生命周期修改。

独立 Catalyst 探测的 `AVPictureInPictureController.isPictureInPictureSupported()` 返回 true；应用内配置也允许画中画。Apple 的 [AVKit 说明](https://developer.apple.com/videos/play/wwdc2021/10290/) 介绍了系统播放器的画中画与控制器生命周期；本轮以系统小窗的实际交互为通过证据，而不是仅凭 API 可用性或代理回调。

本次长视频检查使用生产画廊和本地文件；没有覆盖远端长视频缓冲、跨屏、音频输出、AirPlay、退出账号或关闭主应用后继续播放。Opus 额度尚未恢复，本轮没有联合复核。未改 iOS 功能，不新增只镜像实现的测试。

## 无临时入口构建补验

移除临时文件后，`/tmp/betterchat-pip-final-build.log` 构建成功，应用包中没有验收素材，严格签名与差异检查通过，Package.resolved 未变。

重新打开正常应用，从 Something 已有两秒测试视频进入独立窗口和系统播放器，系统画中画实际出现并显示同一测试色条；小窗播放、恢复原视频窗口、播放到末尾、Esc 退出系统播放器再关闭媒体窗口均完成。截图 `pip-chat-real.png`。此证据覆盖聊天视频的真实入口与媒体解析路径，但不能区分底层缓存命中或新的网络下载，也不替代长视频缓冲验收。

应用最终停在 Something，主窗口 1024×640、系统外观、空输入，没有发送消息或改变 QQ 在线状态。

后续核对发现，上一轮快速退出后立即 getApp 仍可能连接退出中的旧进程，窗口菜单曾残留临时入口。已按完整可执行路径确认 Mac 进程结束，再启动最终构建并核对菜单无临时项；同名 iOS 模拟器进程保持不动。此前真实聊天视频检查使用的播放器代码与最终构建一致，但不把快速重开本身当作新二进制已加载的证据。
