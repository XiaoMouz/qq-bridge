# 搜索失败恢复与离线布局验收（2026-10-14）

本轮由 Codex 实施和实机验收。Claude 上轮额度仍未恢复，本轮没有把独立复核记为通过。

## 修复

- 联系人打开失败与历史搜索失败原来共用一个 error，重试无条件重新搜索。现在分别保存错误；联系人失败对应「重新打开会话」，历史检索失败对应「重试搜索」。重试打开保留已有结果和选择，连续点击不会取消正在进行的打开并错误发起搜索。
- 联系人行的忙碌状态直接读取 `MacChatOpenRequest.peerKey`，取消完成后不会留下第二份 loading 标记；清空查询或离开分区后，过期失败不能恢复错误或触发旧联系人重试。
- 搜索列表下面有加载/错误提示时，列表不再额外保留一份悬浮栏高度的空白；提示本身仍位于底部标签上方。
- `unavailable` 不再一律显示「QQ 掉线了，重新登录后再试」。它也覆盖断网或后端未启动，现在提示「服务暂不可用，请检查连接后重试」。此说明同步用于 iOS。
- 窄窗口离线实测发现连接提示压住搜索框。Mac 全局状态条由顶部 overlay 改为条件 safeAreaInset，有状态时为其留出空间，无状态时不保留空白；通话/横幅继续使用原内容。

修复前两项测试复现 5 个断言失败：请求类型错误、结果被清空、选择丢失、并发错误覆盖、重试再次走错路径。日志：`/tmp/betterchat-search-tests-before.log`。

最终 7 项测试全部通过（`/tmp/betterchat-search-tests-final.log`）：正确重试与结果保留、并发失败独立重试、查询变更后的迟到失败、离开后的迟到打开失败、清空查询后旧重试失效、取消打开后忙碌状态收尾及再次打开、unavailable 说明不误导重新登录。连续重试也在上述用例中覆盖。

测试 action 设置独立环境变量，使 DEBUG 宿主不恢复账号、不注册推送、不访问用户数据库；正常启动没有这个变量。完整命令见 [测试说明](tests/README.md)。

## 实机证据

正常启动时，当前 OrbStack 未运行，Docker socket 不存在，后端日志显示数据库连接终止 / schema 初始化失败，本机 8080 无响应。没有为测试主动停止服务，也没有重启 QQ/NapCat，启动恢复等待用户确认。

利用这一真实不可连接状态检查：

| 状态 | 结果 |
|---|---|
| 1024 深色，搜索 Something | 本地会话结果保留，历史查询失败提示正确；搜索框仍能输入。 |
| 440×480 深色/浅色 | 状态条位于搜索框上方，不覆盖输入；错误文字和重试按钮位于悬浮栏上方。 |
| 点击重试搜索 | 请求后仍返回当前不可连接错误，界面收尾且可再次操作；没有把它记为网络恢复成功。 |
| 窄窗口搜索框 Tab | 本地 Something 结果仍能打开，返回已有历史与空输入；未发送消息。 |
| 1024×640 浅色 | 左右内容对齐在状态区下面，搜索、结果、错误和输入区均可见。 |
